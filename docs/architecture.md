# Архітектура

Проєкт поділено на шари за напрямком залежностей: HTTP → сценарії →
дані. Кожен шар знає лише про сусідній, завдяки чому правила доступу
можна перевіряти без запуску сервера, а транспорт — замінити.

```text
transport/     HTTP-межа: розбір запитів, єдиний формат помилок
identity/      предметна логіка: реєстрація, вхід, блокування
persistence/   SQLite: з'єднання, міграції, запити
settings/      змінні оточення та незмінна конфігурація
site/          віддача клієнтської частини
```

## Чому саме такі назви

Імена модулів описують відповідальність, а не технологію. Тому в
проєкті немає файлів на кшталт `auth_security.py` чи `database.py`:
замість одного «універсального» файлу є `identity/hashing.py`,
`identity/password_rules.py`, `persistence/engine.py`. Такий поділ
робить код читабельним і не повторює шаблон із методичних вказівок.

## Ключові рішення

* **Сервіс не знає про HTTP.** `identity/registration.py` та
  `identity/authentication.py` приймають Pydantic-модель і повертають
  словник або доменну помилку. Їх можна викликати з тестів напряму.
* **Репозиторій — єдине місце SQL.** `identity/queries.py` і
  `identity/mutations.py` містять лише параметризовані запити.
* **Помилки — частина контракту.** `transport/errors.py` описує
  доменні помилки з HTTP-статусом і машинним кодом, а
  `transport/handlers.py` перетворює їх на єдиний JSON.
* **Конфігурація — до першого запиту.** `settings/config.py` читає
  `.env` один раз і віддає незмінний `Settings`.
* **Міграції версійовані.** `persistence/schema.py` застосовує лише
  відсутні кроки, тому повторний старт нічого не ламає.

## Клієнтська частина

`index.html` містить лише каркас сторінки. Екрани збираються з
компонентів у `scripts/components/`: форма входу, форма реєстрації,
огляд облікового запису. Спільні речі лежать у `scripts/core/`
(запити, помилки, робота з формою, форматування), а дрібні віджети —
у `scripts/ui/` (сповіщення, перемикач пароля, вкладки).

Іконки та ілюстрація намальовані вручну у `frontend/assets/` і
підключаються через власний SVG-спрайт.

## Межа у 100 рядків

Жоден файл проєкту не перевищує 100 рядків. Це не формальність, а
спосіб тримати модулі сфокусованими: щойно файл виростає, з нього
виділяється окрема відповідальність. Перевірити можна командою:

```powershell
Get-ChildItem -Recurse -Include *.py,*.js,*.css,*.html |
  ForEach-Object { [pscustomobject]@{
    Lines = (Get-Content $_.FullName).Count; File = $_.FullName } } |
  Sort-Object Lines -Descending
```
