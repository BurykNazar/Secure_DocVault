# Протокол перевірки

Нижче — послідовність дій для звіту. Скріншоти робляться з реального
запущеного застосунку.

## 1. Стан сервісу

```powershell
python manage.py
```

Відкрити <http://127.0.0.1:8000/api/v1/status>. Відповідь містить
`database: ready` і кількість облікових записів.

## 2. Реєстрація

1. Відкрити <http://127.0.0.1:8000/>.
2. Перейти на вкладку «Реєстрація».
3. Ввести ім'я, пошту й пароль, що відповідає всім вимогам.
4. Натиснути «Створити акаунт».

Очікування: повідомлення про успіх, автоматичний перехід на вкладку
входу та підставлене ім'я користувача.

## 3. Перевірка складності пароля

Повторити реєстрацію з паролем `short`. Очікування: поле пароля
підсвічене, під ним перелічені всі невиконані вимоги (довжина, велика
літера, цифра, спеціальний символ).

## 4. Вміст таблиці users

```powershell
python tools/db_report.py
```

Показати рядок `password_hash` (починається з `$2b$12$`) і `salt`.
Відкритого пароля немає.

## 5. Вхід

1. Ввести правильний пароль — з'явиться картка облікового запису.
2. Вийти й ввести хибний пароль — з'явиться повідомлення «Невірне
   ім'я користувача або пароль».

## 6. Блокування

Ввести хибний пароль п'ять разів поспіль. На шостій спробі сервер
відповідає `423` і повідомляє, через скільки хвилин можна повторити
вхід. Навіть правильний пароль не діє, поки триває блокування.

## 7. SQL-ін'єкція

```powershell
python tools/injection_check.py
```

Скрипт надсилає `' OR '1'='1`, `admin' --`, `UNION SELECT` і
`'; DROP TABLE users; --`. Очікування: кожна спроба отримує `401`,
реєстрація з SQL-синтаксисом — `400`, а стан бази лишається `ready`.

Ту саму перевірку можна повторити вручну у формі входу: ввести
`' OR '1'='1` як ім'я користувача й побачити відмову.

## 8. Автоматичні тести

```powershell
pip install -r requirements-dev.txt
python -m pytest
```

Тести покривають хешування, реєстрацію, вхід, блокування та
SQL-ін'єкції. Використовується тимчасова база, робочі дані не
змінюються.
